# Tokenizer：文字怎样变成整数 ID

> 整理日期：2026-10-03。行号对应本次整理的源码；之后编辑源码可能移动行号。数字示例会注明是手算还是实际运行。


模型接收整数，用户输入文字。Tokenizer 在两者之间转换：先拆成 UTF-8 字节，再按已经学好的 BPE 规则合并，最后查词表 ID。解码则查回字节，拼起来还原文字。

像用积木拼文字：基础字节是最小积木，BPE 规则决定哪些相邻积木可以合成更大的块。词表给每块编号；编号本身不代表大小、词义或重要程度。

| 方法 | 输入 → 输出 | 下一步 |
|---|---|---|
| `__init__` | 词表、规则、特殊标记 → 查询表 | encode/decode 使用 |
| `encode` | 字符串 → 整数列表 | 模型或 .bin |
| `_encode_text_segment` | 普通文本 → ID | 预分词、字节化、BPE |
| `_apply_bpe` | 字节块列表 → 合并列表 | 查 ID |
| `decode` | ID 列表 → 文字 | 显示给你 |
| `encode_iterable` | 一块块文字 → 逐个 ID | 预处理写文件 |

## 手算走查：同一份文字跨方法

示例词表包含基础字节 0～255、ID 256 的 `b'ab'`、ID 257 的 `b'abab'`、ID 258 的结束标记。规则依次是 `(a,b)`、`(ab,ab)`。

输入：`abab abab<|endoftext|>abab`。

| 阶段 | 状态 |
|---|---|
| 特殊标记拆分 | 普通段 `abab abab`、标记、普通段 `abab` |
| 普通预分词 | `abab`、` abab`；前置空格保留 |
| 字节拆分 | `a,b,a,b` 和 `空格,a,b,a,b` |
| 第一条规则 | `ab,ab` 和 `空格,ab,ab` |
| 第二条规则 | `abab` 和 `空格,abab` |
| 查 ID | `[257,32,257]`、标记 `[258]`、尾部 `[257]` |
| 最终编码 | `[257,32,257,258,257]` |
| decode | 查字节、拼接，恢复完整原文 |

重叠示例：`[a,a,a]` 使用 `(a,a)` 得到 `[aa,a]`，不是 `[aa,aa]`，因为中间的 a 不能重复使用。

## 常见坑

- `tokenizer.py:40/109` 编码按规则编号，不按新文本里出现次数挑选 pair。
- `tokenizer.py:68/71` extend 追加多个整数，append 追加一个对象，混用会改变列表结构。
- `tokenizer.py:86` 遍历 bytes 返回整数，必须重新包装成 bytes 才能与 BPE 规则匹配。
- `tokenizer.py:138` 替代字符意味着原字节未组成有效 UTF-8，不能假设随机生成 ID 一定解码成正常文字。
- `tokenizer.py:147` 各块独立编码；把 `abab` 切成 `ab` 和 `ab` 可能得到两个 ID 256，而全文得到一个 ID 257。切断特殊标记也会改变结果。
- `tokenizer.py:36/89` 词表需包含基础字节和实际用到的合并块；缺失会查表报 KeyError。

| 概念 | 一句话 | 代码位置 |
|---|---|---|
| 字节 | UTF-8 文本的数值基础单位 | `tokenizer.py:86` |
| 预分词 | 先限制可以合并的片段边界 | `tokenizer.py:11/83` |
| rank | 已学规则的使用优先级 | `tokenizer.py:40/109` |
| 特殊标记 | 完整匹配后直接查一个 ID | `tokenizer.py:64–72` |
| 解码 | 拼字节后恢复文字 | `tokenizer.py:135–138` |
