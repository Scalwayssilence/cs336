# BPE 训练与语料预处理

> 整理日期：2026-10-03。行号对应本次整理的源码；之后编辑源码可能移动行号。数字示例会注明是手算还是实际运行。


Tokenizer 要先有词表和规则。BPE 训练从 256 个基础字节开始，统计语料中频繁相邻的块，把它们合并成更大的块。预处理再使用这个固定分词器，把全文转成整数文件。

像整理常用积木：经常一起出现的两块先拼成一块，减少以后拼接时的步骤。模型训练不负责学习这些合并规则，两个阶段分别保存各自的产物。

| 文件/函数 | 输入 → 输出 |
|---|---|
| `train_bpe` | 文本、目标词表、特殊标记 → vocab/merges |
| `_count_words/_count_pairs` | 文本 → 片段频率、pair 频率和倒排索引 |
| `_learn_merges` | pair 统计 → 按顺序学习的规则 |
| `save_tokenizer_files` | 字节词表/规则 → JSON/TXT |
| `load_trained_tokenizer` | JSON/TXT → 可用分词器 |
| `process_corpus` | 原文、分词器 → 连续 uint16 文件 |

邻居示意：`[x,a,b,y]→[x,ab,y]`，扣掉 `(x,a)`、`(b,y)`，增加 `(x,ab)`、`(ab,y)`。被选中 pair 的统计在整轮处理后清掉。索引集合可能有旧记录，扫描实际内容会跳过不存在的 pair。

## 路径与数据走查

当前 `main()` 使用 `Path(__file__).resolve().parents[2]`。源码在 `仓库/assignment1-basics/cs336_basics/`，因此默认路径实际为 `仓库/assignment1-basics/data/`。run1 使用的是 `仓库/data/`。操作手册用显式函数参数，避免依赖这两个默认入口的路径。

编码例子 `[257,32,257,258,257]` 打包为 5 个 uint16，输出 10 字节。读取要用相同 dtype：

```python
ids = np.fromfile(path, dtype=np.uint16)
```

真实 `.bin` 是连续的一维 ID 流；`get_batch` 取长度 S+1 的相邻内容，组织为 x/y；模型一次预测全部 S 个位置，再与右移答案算 loss。

## 常见坑

- `train_bpe.py:39` 仍一次读入完整原文，倒排索引不等于流式 BPE 训练。
- `train_bpe.py:35` 若目标词表小于 256+特殊标记数，本实现没有完整参数校验，不能按目标大小推断产物。
- `train_bpe.py:64/65` 特殊标记统计按调用方顺序分割；与 tokenizer 的长标记优先机制不同，重叠特殊标记需额外核对。
- `preprocess.py:93` 会删除旧输出，调用前确认路径是你打算重新生成的文件。
- `preprocess.py:72` uint16 只能存 0～65535，扩大词表要同时修改文件格式与训练读取 dtype。
- `preprocess.py:97` 文本块边界可能切断词或特殊标记，当前编码不携带跨块状态。
- `train_bpe.py:215`、`preprocess.py:117` 默认路径在 assignment1-basics/data，仓库根 data 的操作请用显式参数。
